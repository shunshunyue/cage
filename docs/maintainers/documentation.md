# 维护这套文档

文档应帮助读者完成任务，并准确解释框架实际执行的行为。先读公开 API、执行链和消费示例，再组织说明；内容结构由作者判断，脚本承担生成、分发和校验。

## 每类资料回答一个问题

| 资料 | 读者要得到的结果 |
| --- | --- |
| 开发手册入口 | 选择学习路线或直接找到任务 |
| 入门课程 | 从明确前提完成一个可运行功能 |
| 专题指南 | 把一项能力接到现有应用 |
| 参考 | 查参数、默认值、返回、失败和保证 |
| 工具与排错 | 找到证据或第一个失败点 |
| Skill | 编程 AI 按任务判断、协作与验收 |
| AGENTS | 当前项目的入口、代码和环境约束 |
| 设计/验收/发布记录 | 了解特定时间或版本的决定与证据 |

人与 AI 共用教程、参考和源码。入口不重复完整流程或能力边界；通用规则只在主要参考位置展开，任务中保留当下必要的提醒。

## 写作和示例

任务指南从目标、前提、具体位置开始，按真实操作解释输入、执行者和结果，再给成功/失败的验证方法。读者完成基础路径后才进入高级参数。

示例明确区分完整文件与组合片段，说明已有符号、执行目录、当前版本及运行前提。可编译教学源码放 development/examples；正文展示关键部分并解释连接。不要把单次失败经验扩成每页重复的全局禁令。

参数和状态依据公开签名及实现；金额单位、空值、范围、事务、并发、幂等、重试与清理必须准确。发现材料和代码冲突时修正说明，涉及业务目标则先共同确定规则。

## 唯一来源与同步

当前教材在 docs/development；错误解释在 scripts/error-catalog.ts，生成器在 scripts/build-error-docs.ts。AGENTS 托管文字在 packages/cli/src/sync.ts，发现入口由 scripts/sync-agent-skill.ts 生成。

修改上述来源后同步范例、templates/app 与 templates/blank，并重新构建 CLI。客户业务约定留在 AGENTS 托管区外。旧页面保留必要导航，历史记录标明时间与当前替代入口，避免成为另一份用法手册。

## 验证

运行 pnpm docs:check 检查错误册、链接和分发；课程源码变化运行 pnpm docs:examples，维护脚本变化运行 pnpm typecheck:scripts。涉及 CLI 指引再运行相关工具链回归。

链接存在与示例编译不能证明易懂。按[教学评估](agent-evaluation.md)观察新读者实际完成任务，记录阅读跳转、卡点、错误 API、实现结果和验证缺口，再修正造成问题的章节。
