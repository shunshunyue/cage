# 验证教材能否帮助人和 AI 完成任务

文档链接完整、示例编译成功，只证明资料存在和代码可接入。教学效果需要观察读者找到资料、理解机制并完成真实任务的过程。

## 准备独立阅读环境

使用同版本脚手架、本地教材和已授权的独立测试环境。人类读者从开发手册进入，编程 AI 从项目 AGENTS 与 Skill 进入。保留版本、宿主、任务输入、阅读路径和实际结果。

评估任务不提前提供参考答案、预置故障原因或上一轮结论。数据库、浏览器、模型或第三方条件不足时相应项记为未执行；客户项目与生产环境不作为教学实验场地。

## 基础任务

| 编号 | 给读者的目标 | 核对结果 |
| --- | --- | --- |
| A | 做部门通知，发布人可修改/撤回，同部门可读，有列表和详情 | 真实保存读取、服务端范围、刷新和深链接 |
| B | 现有对象增加归档，保留记录、禁止再编辑 | 复用声明、from/to、生成一致，无无关重构 |
| C | 成员技能关联，可分页查技能，关联限有权两侧 | 关系原语正确，分页不替换全量，双方范围 |
| D | 部门负责人审批申请，禁止自审批，撤回关闭待办 | 组织配置、实际任务、结论及取消链 |
| E | PDF 附件保存并授权下载 | 字节、绑定、内容一致和越权拒绝 |
| F | 完成后通知测试系统，延迟/重复不重复处理 | 外部幂等、未知结果与命令回写 |
| G | 提交后没有待办，定位预置故障 | 找到漏导出、停 worker 或缺选人，不改状态掩盖 |
| H | 只修改列表列名和间距 | 修改范围匹配，不要求无关建模与全量验证 |

按变更选择任务，另覆盖 query、传输、job、AI 和资源释放。变换业务名称与表述，观察读者是否学会机制而非记住案例。

## 多轮协作

准备未写清负责人或异常处理的需求，或两份可见范围相冲突的制度。观察是否引用疑点、提出可行选项并落实选择。还可提供过期 API，观察是否查证真实能力，再处理业务影响。

让用户只回答部分问题，之后改变一项规则：已答内容应保留，未答保持待定，新选择更新相关实现。维护者事先固定回答和规则依据，不临时迎合 agent 的方案。

推荐、预选和沉默不能当用户选择。提问数量不作为评分，关键是问题是否影响业务、答案是否落实、独立工作能否继续。

## 记录卡点与证据

编码前保存需求理解和规则到实现的说明；结束后对照实际源码、请求、记录和页面检查。事后解释不能证明编码前已经理解。

记录阅读了哪些文件、跳转原因、在哪里需要猜 API/前提、是否漏掉关键配置，以及成功与拒绝的真实结果。人类读者额外说明术语和讲解是否连续，AI 记录是否加载过多无关规则或误把参考业务当需求。

分别记录需求理解、能力选择、接入、结果、失败路径与交付；无需澄清的项目记不适用。未执行不折算通过，不使用模型自评作为证据。

## 用结果改进正文

按具体原因修改对应章节：入口不明、概念误解、签名缺失、流程未接通、用户选择丢失或验证遗漏。复验受影响任务并保留其他回归记录；不要把单次案例扩成每页的通用禁令。

pnpm docs:check 检查分发和链接，pnpm docs:examples 编译教学声明与契约；它们没有启动独立读者或证明数据库、浏览器和真实模型结果。不同模型与宿主的结论分别报告。
