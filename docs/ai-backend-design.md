# Cage 原生 AI 后端设计草案

状态：保留的架构讨论基线，2026-11-05。原生 AI 首版已开始实现；实际公开 API、运行边界与接入示例以 [智能助理与 AI 审批指南](ai/intelligence.md) 为准。本文保留早期拟定协议，不应直接复制其中配置或路径。

目标是由 Cage 自研统一 Agent Runtime，对外提供两个框架功能：AI 审批节点、本体驱动的全能助理。参考 DeepSeek-Harness 的生命周期、工具反馈和会话组织方式，不引入其运行时依赖。框架负责后端、稳定协议和 SDK；应用开发者或编程 AI 使用 SDK 构建业务界面。

## 1. 已确定的产品与架构边界

| 能力 | 框架负责 | 应用提供 |
| --- | --- | --- |
| AI 审批 | 正式审批节点、通过/退回修改/转人工、任务调度、结果校验、授权、审计和恢复 | 审核要求、可读上下文、人工接管规则、结论命令绑定 |
| 本体助理 | 根据领域声明发现能力，查询数据、解释规则、执行命令、处理待办 | 已有领域声明、准确的业务说明和必要的专门查询 |
| 页面感知 | SDK 页面上下文协议、服务端校验与数据补取、指代解析 | 当前页面标识、对象引用、选择、筛选、显式共享的页面内容与表单草稿 |
| 模型 | 模型适配协议、调用预算、取消、用量记录、连接器传输 | 模型配置与密钥引用 |
| 前端 | SDK、Hooks、事件协议、参考界面 | 样式、布局、业务卡片、导航及交互展示 |

AI 审批可以放在流程任意位置，也允许全 AI 审批。AI 最后一个步骤通过时，可以触发最终通过命令，仍需满足该命令的身份、权限、范围及约束。

框架根据声明派生工具，不要求每个应用另写一套同义的 AI 工具。新增声明通过正常注册、生成和部署进入助理能力目录；工具发现不等于自动授权。

| --- | --- | --- |
| [注册表](../packages/kernel/src/registry.ts) | 聚合、命令、查询、审批、扩展、系统能力目录 | AI 策略引用；节点、规则及工具语义参与版本指纹 |
| [读侧](../packages/kernel/src/read.ts) | get/list/related/run、只读事务、安全视图、掩码与读取审计 | 受控的结构化统计查询、结果来源和覆盖范围 |

| [审批路由](../packages/approval/src/route.ts) | 人工步骤、条件、或签/会签、引擎实例 | AI 步骤、稳定步骤标识、人工接管、退回修改 |

| [outbox](../packages/kernel/src/worker/outbox.ts) | 领取、去重、重试、事务外 IO 分阶段执行 | 独立的 AI 任务处理器；长推理不占住原对象的事件队列 |
| [连接器](../packages/connectors/src/runtime.ts) | 主机白名单、密钥引用、超时、取消、fake | 流式响应和模型传输所需的协议适配 |
| [本体抽取](../packages/cli/src/ontology.ts) | 声明图、字段、关系、状态、输入 schema | 运行时清单、权限裁剪、语义检索与工具发现 |
| [HTTP 上下文](../packages/http/src/ctx.ts) | 用户授权解析与失效处理 | 后台任务使用的身份重解析、流与历史数据访问控制 |

必须显式处理三点：现有命令幂等记录有效期为 24 小时；executeIn 返回内部未掩码结果；systemCtx 默认范围为租户内全部。三者都不能直接当作 AI 的长期去重、对外工具结果或受限自动主体实现。

## 3. 包与模块组织

新增 `packages/ai`，将重型运行逻辑放在独立包中。建议模块如下：

```text
packages/ai/src/
  declarations/       策略声明、引用与校验；模块导入时不做 IO
  runtime/            单次推进、状态迁移、预算、错误分类、取消
  providers/          模型协议、工具调用解析、用量归一化
  context/            页面上下文、本体检索、上下文组装与压缩
  tools/              工具目录、动态发现、读写和审批适配
  sessions/           会话、消息、任务归属与串行执行
  memory/             摘要、长期偏好、来源与失效
  actions/            操作计划、交互、持久回执、恢复
  persistence/        系统表、迁移、租约、事件与数据清理
  worker/             AI 任务处理器及生命周期
  approval/           审批执行器适配，不重新实现审批引擎
  http/               固定 AI 接口的处理逻辑
  protocol/           可供浏览器使用的纯 DTO/schema
```

把 CLI 中可共享的本体模型、索引和纯查询逻辑抽到 `packages/ontology`；静态 TypeScript 分析、源码位置及开发工具继续由 CLI 负责。AI 服务不在用户请求中启动编译器或执行 CLI。

依赖方向：kernel 提供通用声明和执行边界；approval 定义节点与执行器协议；ai 实现运行时并通过适配器消费 approval、kernel、ontology 和 connectors。approval 与 kernel 不反向导入 AI 运行时。

前端从 client 的 AI 入口使用 SDK，protocol 入口不得间接加载服务端模型、数据库或 domain。生成的业务 contracts 继续提供领域类型；不把每个业务工具再生成一套独立 AI SDK。

HTTP 和 worker 分别增加窄的功能装配、后台任务处理器接口，用来注册路由、能力、就绪检查和关闭钩子。AI 提供对应实现。两者从相同发布配置获得模型、策略、注册指纹和工具版本。必须纳入正常停机、健康检查、测试 drain 与配置一致性检查。

## 4. 页面上下文：让助理理解用户正在看什么

SDK 负责向应用页面收集结构化信息。它不能仅根据 URL 自动理解任意组件，也不需要默认抓取整页 DOM。业务页面通过统一 Hook/Provider 注册上下文，编程 AI 在创建页面时完成这部分接入。

拟定数据形状：

```ts
interface PageContextInput {
  pageInstanceId: string; // 页面/标签页实例；不是授权身份
  revision: number;
  capturedAt: string;
  page: {
    id: string;          // 稳定页面标识
    title: string;
    kind: 'list' | 'detail' | 'form' | 'dashboard' | 'custom';
    route: string;       // 只传允许的路由参数，不传认证信息
  };
  subject?: { aggregate: string; id: string; observedVersion?: number };
  selection?: { aggregate: string; ids: string[] };
  view?: {
    aggregate?: string;
    query?: string;      // 已注册查询名
    input?: Record<string, unknown>;
    visibleIds?: string[];
    visibleFields?: string[];
  };
  draft?: {
    command: string;     // 已注册命令的输入草稿
    values: Record<string, unknown>;
    baseVersion?: number;
  };
  visibleContent?: Array<{
    id: string;
    text: string;       // 应用显式共享的页面文本，有限长度
  }>;
}
```

发送消息时捕获该标签页的上下文快照，保存其版本并绑定 run。另一个标签页改变选择、用户跳转页面，不能悄悄改变已提交任务的目标。需要更新当前任务时，走显式的上下文补充交互，记录新快照。

后端接收后按以下顺序处理：

1. 校验 schema、字节数、对象数量、字段数量及同一页面的版本顺序。
2. 校验对象、命令、查询和字段均存在于运行时清单；页面标题只是辅助说明。
3. 从认证结果取得主体，按当前授权经安全读侧补取对象与查询数据。
4. 将后端补取的数据标为已核实事实，包含对象版本、读取时间和来源引用。
5. 将 visibleContent、表单草稿等标为客户端提供的上下文。草稿是未保存输入，不覆盖数据库事实；已掩码内容不能通过页面上传被自动升级为可信明文。
6. 去除隐藏字段、凭证字段及不允许外发的内容。页面上下文、摘要、附件文本都只能作为数据，不能改写工具权限或系统指令。
7. 对“当前单据”“这些记录”等指代优先使用本次消息的 subject/selection；仍有歧义时产生补充输入交互。

读取本次页面可见记录与查询全部匹配记录是两种操作。显式选择使用固定 ID；“所有符合筛选条件的记录”必须重新授权查询并形成有上限的目标快照，不把 visibleIds 当成全量，也不在执行过程中悄悄加入新记录。

用户未保存的表单可以用于解释、校验或生成修改建议；保存仍需明确的命令操作。框架可以返回结构化的草稿修改建议，由 SDK 交给页面处理，不能因此绕过保存命令。

## 5. 身份、授权与会话所有权

助理使用当前用户的受控委托，AI 审批使用受限流程主体。这两类主体由服务端确定，模型和页面请求不能指定 tenantId、userId、capabilities、scopes 或 onBehalfOf。

助理 run 保存用户引用和可失效的认证/委托引用，不持久化浏览器 Cookie 或一份永久有效的 Ctx。每次工具执行、交互确认和敏感结果交付前，重新解析当前身份与授权。用户被禁用、撤权或委托过期后，停止相关操作；需要重新认证时进入等待状态。关闭页面只断开订阅，不等于撤销任务；退出登录撤销与该登录委托绑定的后续执行。

自动审批主体需要声明可调用能力、能力参数和数据范围，并与节点允许的读取/动作取交集。规则编辑权限不授予流程执行权限；修改提示词也不能扩大授权。不要把现有 systemCtx 的默认全部范围直接用作该主体。

对要求真人身份、职责分离或二次认证的约束补足主体适用语义。缺少 userId 不能被解释成已经满足真人约束。允许全 AI 审批，需要显式授权的自动主体和支持该主体的规则；不借用提交人或上一位审批人的身份、额度完成最终批准。

会话、执行流、上下文、记忆和结果均检查租户及所有权。运维人员只能经单独授权读取诊断；默认诊断提供元数据，不自动展示对话和业务内容。

## 6. 运行时本体与能力发现

构建阶段从同一份领域声明生成运行时清单，至少包含 schemaVersion、registryFingerprint、生成时间，以及：

- 聚合、字段、公开说明、关系和状态。
- 命令输入 schema、from/to、invokedBy、能力点、约束元数据。
- 查询输入、读取依赖和说明。
- 审批步骤、条件、结果绑定及 AI 策略引用。
- 业务流程说明和工具能力映射。

运行时清单不默认携带 handler 源码、SQL、隐藏字段及密钥。服务启动时核验其与实际注册表一致，失败时拒绝启用不一致的 AI 能力。当前 registryFingerprint 对扩展只纳入种类与名称，实施时必须把影响执行的路由与策略语义纳入指纹。

检索先使用名称、描述、别名和关系索引，返回带节点 ID、版本和证据来源的子图；需要提升语义召回时可增加检索适配器。向量库不是运行基础设施前置条件。

本体回答“声明了什么、允许什么、依赖什么”。任意 handler 的实际分支不能仅凭图谱推断。无法从声明确定的业务规则需要相应描述、查询或诊断入口，并向模型说明证据边界。

工具发现先按当前主体和应用暴露策略筛选，再按当前任务选择相关工具 schema。大型应用不在每次请求中塞入全部命令。最终执行仍重新检查能力，不能将一次发现结果当作长期授权。

## 7. 工具协议与统一执行入口

每个工具定义包含名称、说明、输入/输出 schema、副作用类别、发现规则、授权规则、执行适配及输出预算。主体、租户、租约和幂等标识通过服务端执行上下文传递，不出现在模型可填写的参数中。

首批工具类别：

| 类别 | 来源 | 执行方式 |
| --- | --- | --- |
| 本体发现、节点和关系 | 运行时本体 | 权限过滤后的索引查询 |
| 对象详情、列表、关联 | 注册表 | ReadSide.get/list/related |
| 已声明查询 | registry.queries | ReadSide.run |
| 通用统计 | 字段与关系元数据 | 受控查询计划编译到安全读侧 |
| 操作解释 | 命令与约束 | 复用授权解释；不宣称能预知 handler 结果 |
| 领域操作 | registry.commands | 用户可调用的命令；走内核流水线 |
| 审批待办及决定 | 审批服务 | 校验任务归属、步骤状态与决定权限 |
| 文件、导入导出 | 对应框架服务 | 沿用其权限、任务和下载检查 |
| 补充输入、操作确认 | AI 交互服务 | 创建结构化交互并暂停 run |

工具处理链固定为：解析调用 → 校验 schema → 解析当前主体 → 检查暴露策略与权限 → 预算检查 → 准备或复用动作记录 → 执行 → 整理结果与来源 → 持久化 → 反馈模型。

AI 审批只获得该节点允许的读取工具和提交裁决能力；不能获得助理的任意写工具。裁决交给审批引擎落实。助理也不能以用户身份直接调用 process-only 结论命令，审批操作必须经过待办服务。

可纠正的字段错误以有限、脱敏的 Observation 返回；权限拒绝不能通过换身份重试。重复无进展调用、不可恢复错误和结果未知分别处理，不能全部送回模型无限重试。

## 8. 通用安全查询

新增结构化查询计划，支持字段投影、封闭的筛选运算、排序、分页、分组及允许的聚合函数。模型生成查询描述，框架生成 SQL。

编译器负责验证字段类型、公开性、敏感权限、关联定义、读取能力和复杂度。所有值参数化，全部数据来源仍是 safe.* 和只读账号。隐藏字段不能通过筛选或排序泄漏；无明文权限的敏感字段不能被用来做推断明文的统计或条件探测。

通用关联仅沿已声明关系，明确集合基数和统计口径；不能默认将任意多表 join 后的行数当作对象数量。需要复杂口径时使用应用已声明的 query。金额、币种、时间范围等语义有歧义时先澄清，框架不能仅凭字段名发明指标定义。

设置 AST 深度、关联数量、分页大小、返回字节数、数据库 statement_timeout 和任务预算。统计超限应报告未完成，不能截取前若干行后把结果宣称为全量统计。

工具结果附带读取时间、查询/对象引用、覆盖范围、截断标记和分页信息。模型依据这些信息解释结论的范围。

## 9. Agent Runtime 的持久状态机

建议 run 状态：queued、running、waiting_input、waiting_confirmation、waiting_task、succeeded、failed、cancelled、expired。running 内再记录当前 phase，例如 assembling、model、tools、settling，便于恢复与诊断。

一次推进：

1. 领取带租约和代次的 run，确认状态、取消标志、截止时间和身份仍有效。
2. 装配指令、相关本体、页面快照、有效记忆、对话和工具结果。
3. 预留预算，选择模型与工具集合，发起一次模型调用。
4. 完整接收并校验模型消息、工具参数和结构化结果；未完成的工具参数不得执行。
5. 将已接受的模型输出和计划持久化，再执行工具。
6. 只读工具可有限并行；写工具按确定顺序执行，必要的关联事务使用已有命令机制。
7. 记录工具结果；需要用户输入或后台任务结果时持久化等待状态并释放 worker。
8. 满足场景的终止条件时结算，否则在剩余预算内进入下一步。

这可以由显式状态转移和 advanceOnce 驱动。循环形式本身不是可靠性的依据；任何允许继续的路径都必须经过预算、状态与租约检查。

同一会话默认只有一个正在推进的 run，新消息按顺序排队。补充输入与确认明确绑定 interaction；页面更新不会自动插队修改正在执行的写操作。

限制包括模型请求次数、工具次数、累计输入/输出预算、单次输出上限、实际执行时限及等待有效期。失败重试、参数修正与上下文压缩同样计费和计数。无进展检测结合工具名、规范化参数、结果摘要和状态变化；允许有意义的重复查询，但限制连续重复且没有新信息的动作。

取消必须到达模型传输与可取消工具。取消不回滚已经提交的领域命令；任务最终结果列出已完成的动作。等待输入不占连接或 worker，也不靠模型循环轮询。

## 10. 模型适配与连接器

模型适配器提供统一的消息、工具调用、文本增量、结构化结果、用量和结束原因。配置声明是否支持工具、结构化输出、流式、图片和用量报告；场景所需能力不足时明确拒绝配置。

模型 profile 保存模型名、连接器/传输引用、输出上限、采样参数和数据外发策略。密钥通过现有 secret provider 取得，只保存引用。模型逻辑依赖统一适配接口，不绑定 DeepSeek 或某一家供应商。

连接器扩展流式传输：覆盖连接、响应头与响应体阶段的取消和超时；限制响应大小；验证分片和完成事件；默认日志不记录原始请求和响应。模型适配器负责供应商消息格式，连接器负责网络边界。

Token 预算由请求前估算、输出上限、累计统计和保守预留共同控制。供应商没有返回用量或请求中断时记为 unknown/估计值，不能记成零或承诺精确费用。压缩模型调用也纳入预算。

测试 provider 能按脚本返回工具调用、错误、超时、取消和裁决，用于确定性回归；真实模型联调单独记录，不把 fake 成功当作模型效果验证。

## 11. 写操作、确认与恢复

模型提出操作后，后端先形成规范化动作记录：actionId、runId、主体引用、命令、目标对象、规范化输入、expectedVersion、策略版本和输入摘要。actionId 由后端生成；模型的 toolCallId 只用于协议关联。

写操作是否需要确认由服务端策略根据操作类型、用户请求和批量规模决定。需要确认时，保存不可变操作快照和有效期，通过 interaction 交给 SDK。确认只针对该快照；字段、对象、数量或版本变化后需重新评估，不能继续使用原确认。

实际执行再次解析授权，校验版本和约束。已有对象的写操作必须明确基于哪个版本；不能遇到冲突就自动换成最新版本重发。

当前 sys.idempotency 保留 24 小时，不足以支撑任意时间后的 AI 恢复。新增持久动作回执，业务命令与成功回执在同一事务提交。恢复时先检查回执，已有结果只交付或重新呈现，不重复执行业务。

桥接复用内核流水线，并统一返回按当前主体呈现的数据。现有 executeIn 的未掩码快照只能用于框架内部事务处理，不能直接进入模型、事件流或普通日志。对外结果需要经过统一呈现、必要的读取审计和当前授权检查。

批量操作先冻结有上限的目标集合，每项有独立动作标识，明确逐项提交或整批原子。当前 executeBatch 会清除共享幂等键，不能直接把它当作 AI 批任务的恢复协议。实施时通过动作回执适配批处理，保留每项成功/失败状态；跨模型轮次不维持长事务。

外部副作用通过连接器及其回执恢复。对外结果未知时先核对状态，不能因为模型想重试就重新发起不安全写入。动作回执保留期应覆盖允许恢复期；清理后保留去重墓碑或拒绝恢复过期 run，不能把旧动作当作新动作。

## 12. 会话记忆与上下文组装

会话事件是历史事实，摘要是可重建的派生物，长期偏好是单独管理的数据。

| 数据 | 存什么 | 如何使用 |
| --- | --- | --- |
| 会话历史 | 用户输入、已接受的回答、交互与工具结果引用 | 按权限和窗口预算恢复上下文 |
| 任务状态 | 已完成动作、当前等待、约束与未解决问题 | 恢复执行；不能仅靠模型摘要决定动作是否执行过 |
| 会话摘要 | 目标、已确认事项、引用与覆盖到的事件序号 | 压缩上下文；记录生成版本和来源 |
| 长期偏好 | 用户明确保存的偏好或应用允许的事实 | 按用户/租户隔离，可查看、修改、删除和过期 |

业务查询结果不默认写成永久记忆，后续需要当前事实时重新查询。工具数据及派生摘要记录来源和授权指纹；权限改变后失效或重新取数，不能从旧摘要向模型再次提供已无权访问的数据。对无法安全细分的历史回答，采用保守的停止交付与重建，而非声称可精确擦除所有派生内容。

已经交付给用户或模型的数据无法通过后续撤权收回。后端负责阻止继续交付、复用和执行，并保留受控审计证据。

上下文装配采用固定层次：框架执行边界 → 场景与已发布策略 → 相关本体与工具 → 页面快照 → 有效记忆 → 当前对话与工具观察。内容块标注来源和可信级别，页面、单据、附件、工具结果中的文本都不会变成授权规则。

上下文压缩保留待处理工具协议、当前交互、已确认操作快照和动作回执引用；不把不可恢复的关键状态只存在自然语言摘要里。

## 13. AI 审批的完整实现

### 节点与数据模型

Step 扩展为人工与 AI 两种执行类型。现有 step(title, approver, opts) 保持兼容，新增接受 AI 配置的重载。AI 节点包含稳定 ID、策略引用、读取范围、模型 profile、预算、接管选人规则和失败处理。

增加 flow.approval_step 作为每个实际步骤的执行记录，人工待办继续由 approval_task 表达，并关联步骤。AI 不伪装成某个 assignee UUID。增加决定记录或等价结构，保存结果、执行主体、规则版本、证据、原因和修改建议。

流程实例保存启动事件、提交轮次和对象版本。审批启动协议需携带提交时记录的对象版本与事件 ID，不能用页面或模型声称的版本代替。为此需要补齐内核 outbox 元数据与审批引擎启动协议。

### 执行链

1. 提交事件启动实例，解析并保存本轮路由与策略快照。
2. 打开人工节点时创建人工待办；打开 AI 节点时，在同一短事务中创建步骤记录和 AI run。
3. AI worker 使用受限流程主体，经安全读侧装配字段及关联数据。不能把内部 routableVars 的系统读取快照直接交给模型。
4. 模型仅返回 pass、return、manual，以及有长度限制的理由、建议与证据引用。
5. 校验证据确实来自本次允许的观察结果；输出不合法时有限修正，耗尽后按运行失败策略处理。
6. 在统一锁顺序的短事务中复核实例、轮次、当前步骤、单据版本和执行租约，再提交决定。
7. pass 推进下一步；末步通过时执行 onApproved。return 执行 onReturned 并结束本轮。manual 将当前步骤转为人工接管，创建待办，当前步骤仍未完成。

本轮退回关闭所有未完成任务。申请人通过应用已有的修改命令修订，再次提交启动新实例并从第一步执行，旧结果不复用。撤回、取消和重新提交都使旧 AI run 失去推进流程的资格；即使取消网络请求失败，旧结果也无法提交。

人工接管之后由原步骤继续。人工通过才进入后续步骤，人工退回走同一退回协议；已有最终拒绝语义仍可保留。找不到接管人时进入可诊断的待处理状态，不能静默通过。

运行错误与业务裁决分开：超时、预算耗尽、provider 错误不是“业务不合格”。若配置失败转人工，记录真实的系统原因和执行来源。

### 结果与业务命令绑定

新增 onReturned，不改写 onRejected 的已有含义。框架管理流程轮次、任务与审核意见；应用命令决定退回后的业务状态。默认可继续使用 id-only 结论命令；如需将理由等映射到领域输入，新增显式的纯映射绑定并校验目标 schema。

最终流程状态、领域结论和关键决定记录共同提交，结论命令失败不能先把流程记成完成。自动主体与人工代理身份在审计中分别记录；不伪造 lastApprover。

## 14. 持久化表与一致性约束

以下是职责划分，实际列和索引在迁移设计中确定。框架内部数据使用现有 PostgreSQL 与连接池。

| 建议表 | 主要内容 |
| --- | --- |
| sys.ai_session | 租户、所有者、会话元数据、默认场景、创建与归档信息 |
| sys.ai_run | 场景、会话或审批步骤引用、身份引用、状态/phase、版本、预算、租约、取消与截止时间 |
| sys.ai_event | 每个 run 的递增序号、事件类型、关联动作/交互、受控载荷或 artifact 引用 |
| sys.ai_artifact | 页面快照、模型输入输出、工具结果、回答正文等内容；来源、访问条件、保留期 |
| sys.ai_action | 操作计划、输入摘要、目标版本、确认绑定、执行状态、持久回执 |
| sys.ai_interaction | 补充输入/确认/重新认证请求、schema、有效期、答复与消费状态 |
| sys.ai_memory | 摘要与长期偏好、来源引用、授权指纹、覆盖事件序号与过期时间 |
| sys.ai_policy_version | 审核策略不可变版本、发布状态、说明、允许读取范围、发布审计 |
| flow.approval_step | 流程实例、稳定步骤标识、类型、状态、轮次和 AI run/人工任务关联 |
| flow.approval_decision | 结果、人工/自动主体、规则版本、依据与意见 |

服务主体授权属于通用身份能力，应在内核/组织授权模型中实现，不藏在提示词或模型配置中。

所有唯一约束和关联包含必要的租户归属检查。需要至少覆盖：同一请求幂等受理、同一 run 的事件序号唯一、同一审批步骤的有效执行唯一、同一动作回执唯一、交互只能消费一次、同一会话按序推进。

AI 系统表不作为普通业务工具直接暴露。内容与运维元数据分开访问；日志只记录允许的标识、阶段、耗时和错误分类。数据清理按会话、内容、回执和审计分别制定保留期。

## 15. AI worker 与恢复

AI run 使用独立数据库队列。领取采用短事务、SKIP LOCKED、租约和 fencing token；每次提交进度或结果必须仍持有有效代次。进程退出或租约过期后可由其他 worker 接管，旧进程的晚到结果不能覆盖新执行。

复用原 worker 的进程生命周期、健康和优雅停止机制，但新增 AI 任务处理器。普通 outbox 的消费者只进行短事务的入队和流程动作，不等待完整模型推理。租户并发、模型并发及队列准入需要跨实例生效，首版可由 PostgreSQL 协调。

崩溃恢复按阶段处理：

| 中断位置 | 恢复方式 |
| --- | --- |
| 模型调用前 | 重新装配当前有效上下文和预算后调用 |
| 模型流未完整完成 | 保留中断记录；未接受的工具不执行，按预算重新尝试 |
| 模型输出已持久化，工具未执行 | 继续已验证的工具计划 |
| 本地命令已经提交 | 读取持久回执，重新核验交付权限，不重复写入 |
| 外部操作结果未知 | 使用连接器协议核对或进入待处理状态 |
| 等待用户 | 恢复 interaction，无需重跑模型或占住 worker |
| 审批已经撤回/接管/重提 | 结束旧 run，禁止推进旧步骤 |

所有重试计入预算。关闭浏览器与取消任务是两种事件；后端状态是 SDK 恢复的依据。

## 16. HTTP 与 SDK 协议

建议固定的框架接口如下，最终命名在实现前固化：

| 方法与路径 | 职责 |
| --- | --- |
| POST /api/ai/sessions | 创建当前用户会话 |
| GET /api/ai/sessions | 分页列出自己的会话 |
| GET /api/ai/sessions/:id | 读取会话与当前可交付历史 |
| POST /api/ai/sessions/:id/messages | 提交消息及页面快照，幂等受理，返回 runId |
| GET /api/ai/runs/:id | 获取任务状态、结果与未决交互 |
| GET /api/ai/runs/:id/events?after=cursor | SSE 订阅或恢复执行事件 |
| POST /api/ai/runs/:id/interactions/:interactionId/respond | 提交结构化答复或确认 |
| POST /api/ai/runs/:id/cancel | 请求取消并返回当前状态 |

页面上下文先随消息提交。运行中需要新页面信息时，后端发出 request_page_context 类型交互，SDK 从发起该任务的页面提供新快照；页面不在或无法提供时明确报告，不把其他标签页内容自动替代。

沿用现有认证、Cookie、CSRF、速率限制和错误协议。202 表示受理，不表示任务或业务操作已经完成。普通网络超时不会自动重发写请求，客户端使用同一受理幂等键核对任务。

事件应覆盖：消息增量、工具开始/结束、交互请求、页面上下文请求、状态变化、回答完成、取消和失败。每个事件携带 runId、sequence、时间与类型；SDK 按序号去重。

首版采用小批量持久化后推送，断线后按 cursor 回放；保留期外的 cursor 返回明确的快照恢复响应。SSE 只是订阅通道，不拥有任务生命周期，也不把 TCP 断开解释成取消。事件连接和持续投送都受当前身份与权限约束。

SDK 负责消息组装、流重连、状态恢复、页面上下文注册、交互响应及账号切换清理。应用 UI 消费结构化数据；数据卡片和导航使用对象引用与应用路由映射，不执行模型生成的 JavaScript。

## 17. 配置、诊断与管理

模型配置、AI 策略发布、自动主体授权、运行记录与用户会话分开管理。新增系统能力进入正常能力目录，生产角色不会自动获得。策略发布记录不可变版本；已经运行的审批继续使用本轮快照，除非通过明确的取消/重新启动操作切换。

用户取消自己的 run 与运维停止某个失控执行是不同权限。运维可以查看元数据、错误分类、租约与预算；读取正文需要另外的访问条件。

将 runId/actionId/instanceId/stepId 与现有 requestId 和 trace carrier 关联。扩展 doctor、timeline 和 capabilities，区分未启用、缺模型配置、策略未发布、授权不足、worker 缺失、清单版本不一致和实际执行错误。

指标至少包括排队时间、模型延迟、工具延迟、步骤和用量、人工接管比例、失败类型、取消延迟、重复执行拦截和恢复次数。记录理由与证据，不要求存储模型私有思维链。

## 18. 实施顺序与交付门槛

下面是开发依赖顺序，最终交付仍包含 AI 审批与具有读写能力的本体助理。

| 阶段 | 交付内容 | 完成判据 |
| --- | --- | --- |
| A：协议与身份 | 页面上下文、run/event/tool/interaction DTO；主体与结果协议 | 明确三种审批结果、身份边界、版本与恢复语义 |
| B：执行底座 | 系统表、模型适配、持久状态机、预算、worker、取消、fake provider | 进程崩溃与重试可恢复，预算和停止可验证 |
| C：本体与页面读能力 | 运行时清单、自动工具发现、上下文补取、安全查询、证据 | 不同通用测试聚合无需定制工具即可被发现和读取 |
| D：动作与交互 | 持久回执、版本、确认、批量结果、SDK 事件恢复 | 模型重复调用、网络重试和超时不会重复提交同一动作 |
| E：AI 审批 | 节点、轮次、自动身份、退回、人工接管、结果桥接 | 全 AI、人机混合、重提、取消及晚到结果均正确 |
| F：完整交付 | HTTP/SDK、参考 UI、诊断、文档、模板和打包 | 新项目仅通过配置与领域声明即可启用两项能力 |

实现框架前保存本体与声明基线。内核改动分别说明必要性，并用真实 PostgreSQL 回归证明身份、事务、范围、掩码和幂等行为。已发布迁移不改写，AI 表与审批表通过新迁移添加，现有人工审批和客户端调用保持兼容。

| 范围 | 关键用例 |
| --- | --- |
| 页面上下文 | 多标签页、跳转后旧任务、过期版本、伪造对象 ID、草稿与数据库冲突、页面文字中的伪指令、分页与全量区别 |
| 权限 | 跨租户、跨用户会话、运行中撤权、用户禁用、登录失效、历史摘要失效、敏感字段统计与输出掩码 |
| Loop | 无工具回答、多步查询、非法工具、非法参数、重复无进展、预算耗尽、流中断、取消、等待用户及恢复 |
| 写入 | 同一受理请求重发、同一动作重复调用、版本冲突、事务提交后进程退出、超过 24 小时的恢复、批量部分失败 |
| 审批 | AI 通过、退回、转人工、运行失败转人工、最后节点自动结束、全 AI、人工接管后继续、重提从头、撤回后结果晚到 |

| 模型效果 | 审核误判、证据完整度、规则理解、工具选择、解释正确性、延迟与成本；与 fake 回归分开记录 |
