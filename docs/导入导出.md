# 导入与异步导出

本页描述 `0.2.0` 的异步 CSV 导入导出接口。`0.1.0` 使用同步导出；升级时请按[升级说明](release-0.2.0.md)统一框架依赖并审查迁移。

框架统一连接 PostgreSQL、保存任务和文件、启动消费逻辑，向前端提供通用 HTTP 接口和 SDK。项目继续使用 `createServer({ domain })` 和框架的 `startWorker({ domain })`，无需自己接数据库、队列或文件目录。

**框架不内置导入导出页面，也不预设哪些业务要使用。** 业务项目自行决定入口、按钮、表单、列名和进度展示。导出对象来自项目声明的聚合；导入操作来自项目声明的用户可调用命令。路径中的 `/api/sys/transfers` 只是框架任务接口，不要求用户进入系统管理或持有 `Sys.ops.*` 能力。

## 启动服务

在 `F:\cage` 执行：

```powershell
pnpm build
# 先确保 .env 指向的已有 PostgreSQL 服务已运行。
pnpm --filter @app/purchase-admin dev
```

`cage dev` 会生成契约、启动 API 和 worker；迁移需审查后显式运行 `pnpm migrate`，启动不自动迁移。接口文档位于 <http://localhost:3000/api/openapi.json>。前端可以在任何实际需要的业务流程中调用下面的 SDK；本次仅适配范例原有导出按钮的异步返回值，没有新增固定业务页面。

独立部署升级时先执行 `cage migrate`，再同时更新 API 和 worker。新增的是框架迁移 `cage:0002_data_transfer`，业务项目不需要手写任务表，也不需要改写已有迁移。只启动 API 时，任务会一直等待 worker。

## 导出能力

前端调用生成契约中任一聚合的 `.export(筛选参数)`，后端立即返回任务。前端可用 `client.transfer(id)` 或 `useTransfer(id)` 查询状态，再展示下载链接。页面离开不会取消已提交的任务，业务界面可通过 `client.transfers(聚合名)` 恢复当前对象的最近任务。

导出使用真实数据库的 `safe` 安全视图，按提交人的数据范围和明文权限处理。一次最多 **100,000 行 / 20 MiB**，超限会使任务失败，需要缩小筛选范围；不会再把前 10,000 行当作完整结果。分批读取使用同一数据库快照，`page` 和 `pageSize` 不限制导出范围。

文件仅提交人可以下载。下载时重新读取账号授权；账号被停用、能力收回，或数据范围、明文权限、部门树发生变化后，旧文件不能继续下载，应重新发起导出。导出与下载都写审计，响应使用 `Cache-Control: no-store`。

## 导入能力

前端把 **UTF-8 CSV** 文本和目标命令能力点传给 `client.importCsv(command, csv, options)`。目标可以是任意业务中当前用户获授权、允许用户调用且使用 `z.object` 输入的命令。单文件最多 **1 MiB / 1,000 条数据记录**。

业务前端可以自己定义上传表单和中文列名，也可读取 `/api/sys/transfers/options` 中的命令字段生成表头。任务完成后用 `client.importReport(id)` 获取成功数、失败数和每行结果，自行展示需要的提示；文件选择、字段映射和页面布局属于业务项目。

例如，某业务命令的输入为 `{ sku: string, available: number }`，CSV 可以是：

```csv
sku,available
SKU-001,100
SKU-002,50
```

规则：

- 表头对应**命令输入字段**，不是物理表列名。可选字段可以省略；空的可选单元格表示不提供该值。修改命令可额外传 `expectedVersion` 控制乐观锁。
- 数字列按数字解析；布尔列使用 `true` / `false`；数组和对象填 JSON，按 CSV 规则对引号转义。字符串形式的金额仍使用字符串。
- 支持 UTF-8 BOM、Windows CRLF、引号内逗号/换行和 `""` 转义。重复表头、未知列、错列、未闭合引号等文件问题在入队前直接反馈。
- 输入校验、权限、范围、状态、约束、不变量、审计、事件和同事务反应全部走原命令。流程专用命令不能经导入绕过调用方限制。框架不会自行选择某个业务命令。
- 默认“部分成功”：正确行提交，错误行及其同事务反应回滚。设置 `atomic: true` 后，任何行失败都会撤销整批业务写入；原本成功的行在报告中标为 `ABORTED`。
- 结果报告只保存记录号、结果码、业务错误码和校验失败的字段名，不回显输入值或命令返回快照。记录号从表头第 1 条开始计算；引号内多行内容仍是一条 CSV 记录。

**导出文件不等于导入模板。** 导出包含 `id/status/version` 等系统列和可能的脱敏值，不能直接把它原样回写。导入前按所选命令的表头整理数据。

## SDK 与 HTTP

`cage gen` 已更新导出方法的返回类型。升级旧客户端时，删除“把 `export()` 返回值直接当 CSV 字符串下载”的代码，改为查询任务、完成后下载：

```ts
import { client, type TransferTask } from '@app/contracts';

// exportUrl、command 都来自当前业务；框架不规定使用哪一个对象或命令。
// 也可优先用 cage gen 生成的“聚合客户端.export()”，获得筛选参数的类型提示。
async function submitExport(exportUrl: string, filters: Record<string, unknown>) {
  return client.post<TransferTask, 'CONFLICT'>(exportUrl, filters, {
    idempotencyKey: crypto.randomUUID(),
  });
}

async function submitImport(command: string, file: File) {
  return client.importCsv(command, await file.text(), {
    atomic: true,
    idempotencyKey: crypto.randomUUID(),
  });
}

async function inspectTask(taskId: string) {
  const task = await client.transfer(taskId);
  if (task.ok && task.data.status === 'completed') {
    if (task.data.kind === 'import') return client.importReport(taskId);
    return client.transferDownloadUrl(taskId);
  }
  return task;
}
```

React 项目还可从 `@app/contracts` 引入 `useTransfer(taskId)`。这个可选 hook 只负责加载状态：等待、处理中和重试中每 2 秒刷新，完成/失败/过期停止轮询；不生成页面。其他前端可直接调用 HTTP 或 SDK，不依赖该 hook。

`client` 自动附带 CSRF 和幂等键。需要主动重试同一业务提交时，保存并显式复用原键，不要重新生成。

| 接口 | 用途 |
| --- | --- |
| `POST /api/{aggregate}/export` | 原有路径，**现在返回 HTTP 202 + 任务对象** |
| `POST /api/sys/transfers/import` | JSON `{ command, csv, atomic? }`，返回 HTTP 202 |
| `GET /api/sys/transfers/options` | 本人可用的导出对象、导入命令及输入字段 |
| `GET /api/sys/transfers?aggregate=聚合名` | 本人最近 100 个任务，可按当前业务对象筛选，不包含原文件和内容 |
| `GET /api/sys/transfers/:id` | 单个任务的状态和计数 |
| `GET /api/sys/transfers/:id/download` | 导出的 CSV 或导入结果 JSON |

两类提交必须带 `Idempotency-Key`（1–200 字符），同一租户和用户的同键同内容返回同一任务，同键不同内容返回 `CONFLICT`。不要把同一个键用于不同任务。收到 HTTP 202 只表示已入队，不能视为业务成功。

任务状态：`queued`（等待）、`processing`（处理）、`retrying`（重试）、`completed`（处理结束）、`failed`（任务失败）、`expired`（过期）。`completed` 的导入仍可能有失败行，应读取 `result.failed`，再由业务界面区分“全部成功”“部分失败”和“整批回滚”。

## 持久化、重试及当前边界

- 任务、输入和文件都保存在 PostgreSQL `sys.data_transfer`；outbox 仅携带任务 id。API 与 worker 可以运行在不同机器，不依赖共享磁盘。
- 导入业务写入、逐行结果和消费去重记录在同一事务提交。执行中 worker 中断时一起回滚，重投不会重复写入；数据库故障走既有重试/死信链路。
- 原始文件在完成或业务失败后清除。任务从提交起有效 24 小时，到期立即拒绝下载；worker 每小时清除过期文件和结果。轻量任务索引保留以识别旧幂等键。数据库备份按部署者的备份保留策略管理。
- 超限或无权限属于业务失败；worker/数据库故障可重试。运维可通过原有死信页面处理耗尽重试的任务；运维能力本身不授予他人的文件下载权。
- 当前支持 CSV，暂不支持 XLSX、对象存储、断点续传、逐行实时进度和超大文件流式导入。整批导入上限用于约束事务长度；更大规模需要专门的任务拆分设计。
- 本次内核改动仅增加与业务无关的文件任务服务，复用原读写和 outbox。发布前按仓库 `AGENTS.md` 由架构负责人评审，并在新版本发布；不能覆盖 npm `0.1.0`。
