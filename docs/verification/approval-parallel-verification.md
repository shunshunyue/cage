# 框架 AND 并行审批验收记录

本文保留当时的验收结果；其中审批额度及相关失败用例属于旧实现，现已移除。当前规则与验收应以审批指南和现有测试为准。

日期：2026-11-07。范围是 Cage 原生引擎的结构化并行分支与全部汇合；保留现有领域命令、授权、事务和审计边界。

## 本次交付

- `parallel(title, ...branches)` 与 `branch(title, ...nodes)`，分支内部可多步、带条件及嵌套 AND。每组 2–16 个具名分支，最多 128 个办理节点、512 个结构节点和 8 层容器。
- 实例启动时展开条件并冻结前驱、分支路径和路由内容指纹；使用现有 `steps` JSON 与唯一节点记录，无新增 DDL 或历史迁移改写。旧实例没有执行元数据时按相邻顺序继续。
- 实例行锁内完成节点、开启满足全部前驱的节点及执行最终领域命令；任一分支驳回/退回结束本轮，取消关闭全部活跃分支。最后命令拒绝时本次票、节点和业务共同回滚。
- 多分支待办、候选领取、前后加签、AI 回执、独立节点 SLA 和提醒协同工作；修复其他分支终止后，迟到 AI 失败覆盖已关闭节点的问题。
- SDK/HTTP 提供 `branchPath`、`currentSteps`、`activeSteps`、`definitionVersion`；并行催办要求完整 `expectedSteps`。Admin 展示全部当前环节，CLI 静态图展示真正的分叉/汇合。
- 采购页面仅消费框架分支与历史信息，移除写死顺序的说明；独立演示装配声明采购路径，不在采购业务实现调度、锁或提醒。

路由内容指纹不包含领域命令实现，不表示已有完整版本发布、混合版本部署或在途迁移。API 与 worker 仍需同版本部署。没有统一末端终审时，最后完成分支的人员承担最终领域结论，仍需通过最终命令的能力、范围、额度等约束。
