# 事务、异步、审计与运行边界

本页说明执行保证，供需要判断并发、恢复和部署的人查阅。业务怎样连接事件与外部系统见[自动化指南](../guides/automation.md)，基本流程见[执行模型](../getting-started/architecture.md)。

## 事务中的变化

一次命令的业务记录、关系链接、文件绑定、版本、成功审计、outbox 和 same 反应共同提交。约束、handler 拒绝、不变量或后续同事务命令失败都会回滚。

新建对象先形成草稿，再检查最终字段及创建后的范围。已有对象按范围加锁，检查 from 和可选版本；to: null 保留加锁读取到的状态。反应目标仍走命令流水线，同事务递归有深度限制。

manyToMany 的新增目标在事务内校验租户、可见性和读取能力，源记录版本共同递增。附件的字节上传在业务事务外，ready 文件由命令事务绑定；业务失败不会把临时文件伪装成正式附件。

## outbox 与 worker

outbox 事件在主事务提交后可见。worker 按消费者记录执行与重试；同聚合顺序和死信可能阻塞后续动作。重试后的业务必须仍符合命令状态、授权和幂等要求。

API 和 worker 需要相同版本、domain 和必要引擎。worker 启动检查消费者，发布注册指纹与心跳；缺少消费者不能当作事件处理成功。停机先停止领取、取消可取消 IO，再有界等待在途工作。

reactionEach 对有界集合排序后串行调用。same 整条回滚，outbox 集合随该消费者事务提交；order 描述同事件同事务组的显式步骤顺序。逐项、整单或分批的业务含义由应用决定。

job 只查询 reads、调用 calls 中的命令；本地标记与数据库互斥避免同一调度重叠。连接器限流、认证并发及 AI 并发按进程控制，多实例共享预算需要另外设计。

## 外部写入与未知结果

出站先在短事务领取执行意图和租约，再执行远端 IO，保存回执，最后用短事务调用回写命令。回写失败可以复用已保存的成功回执。

远端幂等键在声明键前带租户前缀。retryableWrite 只有在远端确实支持幂等时才成立；不可重试 write 在超时或中断后可能进入 unknown，此时普通死信重放不会重新外呼。

当前没有通用的远端确认回执或解除 unknown 的管理入口。按实际协议核对远端，制定受控恢复或补偿；超时不能证明对方没有执行。升级在途出站时还要核对版本、键和远端事实。

## 审计交付矩阵

| 入口 | 当前保证 |
| --- | --- |
| 成功命令 | 与业务和 outbox 同事务，审计失败回滚 |
| FORBIDDEN、NOT_FOUND、CONSTRAINT_VIOLATED 拒绝 | 异步尽力记录，失败有日志 |
| 密码登录失败 | 等待尝试记录，记录失败仍拒绝登录 |
| get/list/related 的潜在敏感明文 | 可靠审计完成后才交付 |
| query | 按 reads 保守记录潜在明文；purpose 另做可靠用途审计 |
| 导出生成与下载 | 可靠审计，下载重新核对当前权限 |
| 导入 | 任务提交与目标命令按各自事务记录 |
| 普通掩码读取、诊断元数据 | 默认没有统一专门审计 |

可靠读审计失败使用 CAGE-AUDIT-001，拒绝交付数据。成功登录、step-up、退出当前没有统一专门审计。“有审计”不能扩展成所有请求都可靠留痕。默认结构化日志只保留允许的元数据，不输出原始载荷、密钥或外部错误正文。

## 数据库、缓存与健康

APP、READ、MIGRATE 使用同一已有库，不同账号隔离职责。safe 视图由不能登录的 cage_view_owner 持有，业务读取使用只读账号。连接已有库不等于接管其中任意历史表。

授权变更通知使上下文缓存失效；监听故障时停止复用缓存并重新读取，恢复后清理旧状态。healthz 表示存活，readyz 还反映数据库与授权监听健康。

静态注册和磁盘源码不能证明运行进程已经加载新版本。需要实际进程、迁移、事件或授权证据时使用[诊断工具](../tools/diagnostics.md)，缺失项保留 unknown。
