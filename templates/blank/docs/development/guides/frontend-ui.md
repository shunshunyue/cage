# React 前端与组件库

本指南约束 Cage 应用中的 AI 生成式 React 开发。AI 在开发阶段根据业务需求编写、修改并验证真实 `.tsx` 页面与组件；运行时仍是普通 React 应用，不引入页面描述语言、schema 渲染器或固定 CRUD 页面模板。

## 组件库选择

Cage Web 默认使用 Ant Design（`antd`）和 `@ant-design/icons`。Ant Design 提供覆盖面完整的 React 控件、中文 locale、表格/表单/反馈组件和成熟文档，适合由 agent 按具体页面组合使用。通用 React 生态中也有 Mantine、MUI 等选择；本仓库采用 Ant Design 是为了统一范例和模板的默认组件接口，不要求业务页面套用某种固定版式。

需要构建对话、消息气泡、提示词或 AI 推理步骤等 AI 原生交互时，可以评估 Ant Design X；普通表单、详情、筛选、数据表格仍使用 `antd`。模板不预装这项可选依赖，只有用户需求确实包含这类交互时才添加。不要把 ProComponents 或整套后台脚手架作为默认页面生成方式；它们的高层 CRUD 约定容易把页面形态固定下来，而真实字段、操作与范围必须由业务需求和 Cage 契约决定。

## 应用入口与调用边界

范例和模板已在 Web 入口安装 `ConfigProvider`、简体中文 locale、共享主题 token 与 Ant Design `App` 上下文。生成组件可从 `antd` 和 `@ant-design/icons` 导入控件；需要消息、通知或确认框时，在 React 子组件中调用 `App.useApp()` 返回的方法，使反馈使用入口提供的上下文。不要在模块中重复创建 Provider，也不要使用无法继承应用上下文的静态反馈 API。

页面仍按 `apps/web/src/modules/<module>` 组织，并从模块公开入口导出，由 `app` 层组合到 React Router。筛选、排序和分页等可分享状态进入 URL 查询参数；列表和详情使用各自稳定 URL。组件状态只保存尚未提交的交互草稿，不代替服务端记录。

业务数据使用生成契约和 Cage Client/现有 hooks：读取经过安全读侧，写操作调用对应命令，并处理 `CageResult`、并发冲突和查询刷新。前端 `can()` 只控制入口或按钮显示，服务端仍执行能力、数据范围和业务状态检查。不得为了让生成页面看起来完整而增加伪造统计、静态仓储或绕开契约的直接数据库访问。

## 生成页面的组合准则

- 先按当前任务选择控件：`Form`/输入组件负责编辑，`Table` 负责需要行列比较的数据，`Descriptions` 负责详情字段，`Tag`/`Badge` 表示已有状态，`Result`/`Empty`/`Skeleton`/`Alert` 分别表达结果、空态、加载和错误。
- 用 `Layout`、`Flex`、`Grid`、`Space`、`Typography` 和局部 CSS 建立页面层次；页面布局由任务决定，不为每个区块机械套卡片，也不生成与用户目标无关的仪表盘。
- 优先使用 Ant Design 的 `Button`、`Input` 等组件 props 和主题 token 表达样式与状态。不要把现有业务 CSS 类（如 `.primary`）直接赋给 Ant Design 控件；项目里的旧全局原生按钮规则与其业务类仅服务于原有 DOM 页面。
- 图标从 `@ant-design/icons` 按需导入；只有图标含义不明确时加 Tooltip，主要操作按清楚的文字命名。
- 每个页面自行呈现真实加载、空结果、请求失败、无权限和提交中状态；避免通过组件默认值把未知状态渲染成零或成功。
- 表格给稳定的 `rowKey`，分页与筛选变化同步 URL 和服务端查询；不能只在当前页本地过滤服务端分页结果。
- 表单校验帮助使用者尽早发现输入问题，不能取代服务端 schema、领域不变量或权限校验；成功后按现有查询键刷新数据，失败时保留输入并显示可处理的原因。
- 保持布局在窄屏可用，避免固定宽度、横向溢出及把操作只放在 hover 上；可复用的业务组件留在所属模块，只有确实跨模块复用时才进入 `shared`。

实现前阅读相关页面、模块入口和契约类型。组件库提供的是可组合的 UI 原语，AI 应根据实际业务含义选择与组织它们；组件本身不会生成 Cage 领域声明、API、授权或持久化行为。
