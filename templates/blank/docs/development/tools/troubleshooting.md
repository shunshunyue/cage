# 从第一个失败点排错

从用户刚做的动作开始，沿页面、请求、命令、事件和读取逐段核对。先保留稳定错误和关联标识，再修复最早一个与预期不符的边界。

## 先收集最小证据

记录操作、账号角色与范围、对象 ID、时间及预期结果；保留完整 code / at / reason / fix，以及 requestId、outboxId 或任务 ID。

配置排查只报告主机、端口、库名和错误码。不要输出 .env、密码、Cookie、初始凭据或原始敏感载荷。CAGE 码查[错误码册](../../errors/README.md)，HTTP/业务结果查[运行时错误](../../errors/runtime.md)。

例如契约与声明不同步时，保留的是可处理的诊断节选，而不是整份环境或登录 Cookie：

```json
{
  "code": "CAGE-GEN-001",
  "at": "packages/contracts/src/aggregates/note/index.ts",
  "reason": "生成契约与当前声明不一致",
  "fix": "运行 cage gen，并审查生成差异"
}
```

## 根据现象定位

| 现象 | 先核对 | 修复后看什么 |
| --- | --- | --- |
| 点击没有请求 | 事件处理、按钮状态、实际契约调用 | 浏览器产生真实请求 |
| 契约或图节点缺失 | domain 逐层导出、显式命令名、生成版本 | check/gen 后出现同一声明 |
| 401 | 会话、Cookie、CSRF 和账号 active | 登录恢复后原操作可继续 |
| 403 | 能力、调用身份、角色政策 | 允许主体成功，缺能力仍拒绝 |
| 404 | 对象、租户和范围 | 用有权账号独立读取，不泄露存在性 |
| INVALID_INPUT | 字段路径、命令 schema、分页/过滤参数 | 合法输入成功，非法输入仍失败 |
| INVALID_TRANSITION | 当前真实状态和 from | 操作前提符合，页面同步新状态 |
| CONFLICT | 对象 version 或任务 revision | 重读、用户核对后再提交 |
| CONSTRAINT/INVARIANT/DOMAIN_ERROR | 硬约束、最终条件和 domainCode | 业务反例保持拒绝 |
| 接受任务但结果没完成 | worker、消费者、任务终态和时间线 | 最终记录或报告可读取 |
| 服务端正确、页面旧数据 | 查询失效、URL 和账号缓存 | 刷新与切换用户均正确 |

cage doctor 汇总静态和运行证据，cage explain 观察授权，cage timeline 查看实际异步记录，使用前提见[诊断工具](diagnostics.md)。

例如同样是“保存失败”，原因对应不同修复，不能统一重试或放宽权限：

| 输入或现场例子 | 对应判断 |
| --- | --- |
| 已归档记录再调用 Note.update | INVALID_TRANSITION，核对业务是否本应允许 |
| 记录 version 已是 4，页面仍传 3 | CONFLICT，读取并让用户核对 |
| 没有 Note.archive 却直接发请求 | FORBIDDEN，按已确认角色规则核对授权 |
| 标题只有空格 | 输入校验拒绝，保留输入并提示字段 |
| HTTP 202、任务仍 queued | 任务已接受，继续查询而不是显示全部完成 |

## 提交成功却没有审批待办

确认提交命令确实进入预期状态并发出 start 事件；approval 与 route 的 process 一致、声明均导出，worker 加载同一版本。

再看消费者错误：负责人是否配置、角色是否有成员、字段选人是否有效、账号是否 active、候选/本人清单是否符合当前权限。单据 pending 不等于当前账号有待办，候选还需先领取。

决定失败时核对任务 revision、委派/等待阶段以及结论命令的能力、范围、职责分离和提交版本。流程成功结论仍可能被领域规则拒绝。

例如申请已 pending，worker 的启动消费者报负责人缺失：先在真实组织中配置负责人，再观察受控恢复结果。若当前任务是 candidate 且未领取，本人 pending 清单没有它并不代表流程没生成任务，应查候选池。

## 外部、文件和导入导出

外部超时可能已经远端成功。先查连接器执行与回执，unknown 需要按协议核对，当前没有通用解除未知状态接口；普通重放不应绕过隔离。

例如 ERP 查到同一业务键已经生成单据，而本地超时：不要换一个幂等键再推一张，先核对保存的回执和回填状态。

上传 ready 还未绑定业务；检查命令是否接收文件字段、上传目标和当前状态是否匹配。下载重新检查当前业务授权，取消上传不能移除已绑定附件。

例如 PDF 已到 ready，但创建便笺因标题为空被拒绝：修改标题后重新提交绑定；不能把上传完成直接当作便笺已保存。

导入导出先读任务终态，再看报告、权限变化与过期时间。程序错误和基础设施失败应作为任务失败/重试处理，不改成成功空文件或普通坏数据行。

例如导出任务已 completed，却在下载前撤销权限，应检查当前授权拒绝；任务仍 processing 时没有下载文件，则继续观察 worker 与终态。

## 最小修复与复验

保持权限、状态、约束、门禁和历史迁移有效。错误来自声明就改声明并生成，来自运行版本就构建/重启，来自授权或配置就修正对应配置；修复后复现同一操作及相关拒绝场景。

独立说明已通过、程序跳过和未执行的检查。unknown、HTTP 202、fake 或类型通过各有证据范围，不能直接报告全部业务完成。

例如修复漏掉的 domain 导出后，重新生成并用原账号执行原操作，再用缺能力账号确认拒绝仍在；如果只跑过类型检查，就在交付中明确浏览器和实际写入尚未验证。
