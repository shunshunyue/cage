# 手写源码的详细中文注释

详细中文注释是框架、范例和业务应用的代码交付内容。后续开发者应能从源码理解“做什么、为什么、怎样完成、哪些条件下成立、失败怎样处理”。聊天说明和外部方案不能替代源码中的解释。

## 覆盖哪些地方

新建文件同步写说明；修改文件核对职责及本次涉及的声明、字段和流程，并更新受影响的调用方、消费者与测试。纯注释任务保持逻辑、接口、配置值和运行文案不变。

TypeScript/JavaScript 的文件和公开 API 使用 JSDoc，关键步骤就地注释；CSS、SQL 使用合法注释。测试、脚本、入口、组件和 hooks 也属于手写源码。JSON 保持合法语法，在邻近文档说明。

生成契约、SQL 和派生代码从声明/生成器维护注释。已执行或已发布迁移不因补注释改写。

## 文件头先给阅读路线

写明稳定的职责、上游和下游，以及主要执行顺序和运行边界。入口说明装配哪些服务，纯 index 说明对外公开什么；持久化、缓存、异步和 IO 文件说明由谁创建、关闭和清理。

```ts
/**
 * 便笺详情页，由 app 路由挂载到 /notes/:id，使用生成契约独立读取对象。
 * 本地只保存编辑草稿；提交带服务端版本，成功重读，冲突保留草稿供用户核对。
 * 会话与查询缓存由应用会话层管理，按钮权限只影响显示，服务端执行真实授权。
 */
```

文件头不维护容易过期的行号和完整依赖清单。具体规则靠近声明，复杂分支靠近实现。

## 公开 API 和类型

| 对象 | 说明内容 |
| --- | --- |
| 函数、方法 | 用途、调用阶段、真实参数、返回、输入是否被修改、IO 与失败 |
| 类和成员 | 创建者、持有者、状态、生命周期、并发和关闭责任 |
| 常量和声明 | 业务/协议含义、来源、单位、默认值及变更影响 |
| 接口和类型字段 | 来源、格式、单位、可空/可省略、缺省意义、读写边界 |
| 组件和 props | 页面职责、输入/事件、状态归属、权限提示与成功失败交互 |
| hooks 和返回字段 | 触发、订阅、状态、操作完成条件、取消、缓存及错误责任 |

用真实参数名写 @param，返回语义写 @returns，实际会抛出的错误写 @throws。配置声明没有顶层函数参数，不为填标签编造参数；转导出保留原 API 的 JSDoc，入口说明公开职责。

```ts
/** 导入执行摘要，供业务页展示任务终态；报告不携带原始单元格敏感值。 */
export interface ImportSummary {
  /** 数据行总数，不含 CSV 表头。 */
  rows: number;
  /** 已提交成功行数；整批原子失败时为 0。 */
  succeeded: number;
  /** 失败或被原子回滚的行数。 */
  failed: number;
}
```

## 领域声明要说明实际业务

聚合解释身份、生命周期和一致性边界；字段解释由谁填写、能在哪些状态修改。金额写币种/精度，数量写单位，时间写格式/时区；null、缺省、空字符串和空集合分别说明。

命令写输入、from/to、调用身份、能力与范围、reads、变化和失败；事件写事实、载荷来源和版本；反应写映射、跳过条件、事务与资源；审批写选人和结论责任；query 写依赖、安全视图和输出；job/connector 写幂等、重试和未知结果。

结构化 description、describe、labels 供框架抽取，JSDoc 供维护者理解。二者需要一致，注释本身不会产生状态、权限或图谱关系。

## 复杂流程解释边界

多阶段函数、SQL 构建、递归、缓存合并、重试、并发与清理都要解释实际次序。关键分支交代成立条件和影响，不只翻译 if/for 语法。

```ts
// 旧页面仍保留用户草稿；冲突后只重读服务端版本，避免自动覆盖其他人刚提交的内容。
if (result.code === 'CONFLICT') await query.refetch();
```

对事务说明共同提交与外部步骤；对重试说明键、次数和未知结果；对缓存说明失效、身份切换和迟到响应；对清理说明何时开始、能否重入及失败后如何继续。没有实现的保证不能写成“始终”“自动恢复”或“恰好一次”。

脚本说明前提、输入来源、写入/覆盖/删除范围与可重跑条件，Windows 路径操作明确所有权。测试说明业务意图、夹具和覆盖边界；框架性质与业务结果区分。

## 交付前逐项核对

逐个检查本次文件：职责与调用关系是否完整，导出 API/字段是否能被正确使用，关键分支是否解释条件与保证，注释是否和实际默认值、失败、权限与事务一致，生成物是否从来源维护。

注释质量按信息判断，不按字数、行数比例或机械逐行翻译。名字清楚不能免除必要说明；同样，重复模板和语法复述也不能代替业务解释。
